# AI Instructions

1. Read the relevant Knowledge Base documents and inspect the actual repository before making changes.
2. Explain the current implementation before proposing a solution.
3. Provide a minimal plan, acceptance criteria, and an exact list of files to modify.
4. Implement one small step at a time.
5. Do not rewrite unrelated code.
6. Do not change the existing diagnosis API contract unless necessary and explicitly approved.
7. Do not add dependencies without justification.
8. Never place API keys or secrets in source code, prompts, documentation, or Git.
9. Add or update tests for new behavior.
10. Keep catalog operations local; do not introduce backend endpoints or AI calls for the catalog.
11. Inspect `git diff` after each implementation step.
12. Run relevant build and test checks and report actual results.
13. Update documentation to match the final implementation.
14. Do not claim that tests passed unless they were actually executed.
15. Do not commit automatically unless explicitly requested.
